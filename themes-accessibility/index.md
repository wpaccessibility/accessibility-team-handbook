# WordPress theme accessibility

Creating a theme that supports accessibility is mostly about setting healthy defaults. This includes:

- ensuring the menus are accessible from the keyboard,
- checking that default color contrast meets standards,
- that the HTML structure uses semantically correct code.

Extended information about web accessibility and how to test and to apply this for your work can be found in the [WP Accessibility Knowledge Base](https://wpaccessibility.org/docs/accessibility-ready/).

## Guidelines for themes

The accessibility standards for WordPress themes, submitted to the WordPress Theme repository, are available in the [Theme Handbook](https://developer.wordpress.org/themes/classic-themes/functionality/accessibility/).

The guidelines for the WordPress theme directory’s [accessibility-ready program](https://wpaccessibility.org/docs/accessibility-ready/) are documented in the WP Accessibility Knowledge Base, including testing instructions, so you can check your own theme. The `accessibility-ready` guidelines are additional to the theme guidelines.

**Note**: accessibility-ready does not mean a theme meets the [Web Content Accessibility Guidelines](https://www.w3.org/WAI/WCAG22/quickref/) at level AA. It means that the theme reaches the minimum standards that the theme review team has set.

## Find accessibility Ready themes

In the [Themes Directory](https://wordpress.org/themes/) on WordPress.org, select the ‘Accessibility Ready’ option in the Feature Filter to browse [themes tested against the “Accessibility Ready” guidelines](https://wordpress.org/themes/tags/accessibility-ready/).

![WordPress.org themes directory filter with Accessibility Ready tag checked.](https://make.wordpress.org/accessibility/files/2026/07/a11y-themes-filter.png)

**Note**: Do you want to get your theme listed as ‘Accessibility Ready’ in the Themes Repo? See the [themes review handbook](https://make.wordpress.org/themes/handbook/review/accessibility/) for more information.
